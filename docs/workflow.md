# コード駆動開発のワークフロー

このリポジトリは **設計書 (wiki)とコードを往復させながら** 開発します。
設計書は一度書いて終わりではなく、コードと一緒に育てる「生きた知識ベース」として扱います。

## 基本の流れ

1. **設計書 → コード**
   `docs/design/` の該当ページを読み、その内容に沿って実装する。
   設計書にない振る舞いを実装する場合は、先に設計書へ追記して合意する。
2. **コード → 設計書**
   実装して分かったこと (API の形、制約、変更した判断)を設計書へ反映する。
   コードと設計書が食い違った場合は、 **食い違いを放置せず**どちらかを直す。
3. **記録**
   wiki を変更したら [log.md](log.md) に1行追記する。

## ルール

- 1ページ = 1つのテーマ。他ページとは相対リンクで結ぶ。
- 事実と案を分ける。確定していないことは「案」「未決定」と明記する。
- 実装が存在しないものを、あるように書かない (`status: draft` にする)。
- コードを変更するときは、関連する設計書・利用ガイドも同じ変更 (同じコミット/PR)で更新する。
- 決定事項は [design/decisions.md](design/decisions.md) に集約し、各ページからリンクする。
- 新しいページを作ったら [README.md](README.md) の一覧にも追加する。

## LLM (Claude Code)への指示

- 作業の前に [README.md](README.md) を読み、関連ページを確認する。
- 実装後は、関連ページの `status` / `updated` を確認し、ずれがあれば更新する。
- 設計に影響する判断は、勝手に決めず `decisions.md` の未決定事項としてユーザーに確認する。
- 定期的な整合チェック (lint)では、リンク切れ、README への未登録、`outdated` の放置、設計書とコードの差分を探す。
